# Feature: F5.2 live cost from model pricing (ocswarm)

## Objective

Real costUSD in the hub. Today the hub trusts `session.usage.updated`'s `cost`
field, but real captured events carry `"cost": 0` — the dashboard shows
`$0.0000` with millions of tokens. Compute cost from model pricing instead.

## Root cause (evidenced)

- Fixtures: `{"sessionID":"...","cost":0,"tokens":{"input":6548,...}}` — the
  server-side cost field is unpopulated.
- `src/hub/hub.ts:364`: `agent.costUSD = asNumber(data, "cost") ?? agent.costUSD`.

## Design decisions (pre-delegated)

- **Pricing source**: the server plugin's `ctx.model.list()` (plan.md line 71)
  — models.dev pricing already ships inside the OpenCode server: local-first,
  zero network, same source OpenCode itself uses. LiteLLM's JSON (OpencodeBar's
  source, plan line 126) is rejected: 2MB network fetch + drift.
- **Injection keeps the hub pure**: `createHub(deps?)` gains optional
  `pricing?: (model: { providerID: string; modelID: string }) => Rate | undefined`
  with `Rate = { input: number; output: number; cacheRead: number; cacheWrite: number }`
  (per million tokens). No rates → cost stays 0 (never fabricate).
- **Model identity**: `session.usage.updated` carries no model — the hub tracks
  the session's last `model: { id, providerID }` from `session.step.started`
  (event already parsed there for the F5 name backfill) and prices usage with
  it. No model seen yet → cost 0 until the first usage after a step.
- **Cost formula** (per million): `input×input + output×output +
  cacheRead×cacheRead + cacheWrite×cacheWrite`. The `reasoning` token bucket is
  NOT billed separately (fixture shows output ≥ reasoning → reasoning is part
  of the output bucket; double-counting would inflate).
- **Wiring**: `src/index.ts` builds the rate map from the plugin context's
  model list and injects it. Server plugin context types in
  `node_modules/@opencode/plugin/dist/` are ground truth; if no model/pricing
  API is exposed there, the writer STOPS and reports instead of inventing a
  network fallback.

## Constraints

- Hub stays 100% pure/testable (pricing is injected data). Existing
  `createHub()` callers/tests unaffected (optional deps, default = no rates).
- TUI/web untouched — they already render `costUSD`.

## Known limitations (documented, not defects)

- **Lección estructural del plugin API**: dentro de `setup`, todo
  suscriptor de `ctx.event` debe registrarse antes del primer `await` —
  suscribir después de un gap async desconecta el tap silenciosamente
  (sin error, sin log). Fire-and-forget + resolución diferida es el patrón.
- Pricing base = entrada sin tier del array `cost` de ModelInfo (fallback:
  primera entrada); tiers por contexto largo no se seleccionan por tamaño de
  sesión (los fixtures reales no mostraron sesiones que crucen tiers).
- El hub es in-RAM: tras reiniciar el daemon, las sesiones previas no
  aparecen (los eventos de OpenCode son live-only, no hay replay).
- `opencode run` en background shell errora por permisos (gotcha conocido);
  `--standalone` es un proceso aislado cuyo bus nunca pasa por el daemon —
  el único E2E válido del hub es actividad real del daemon (TUI del usuario
  o turnos de la sesión orquestadora).
