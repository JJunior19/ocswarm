# Feature: F5.1 session-scoped views (ocswarm)

## Objective

Per-session diagrams in the dashboard. Today every root session's tree renders
mixed in one force layout; the user runs several orchestrator sessions (each
with its own subagents, possibly across projects) and needs to view one
session's diagram in isolation.

## Design decisions (pre-delegated)

- **View state**: `view: "all" | <rootSessionID>` in App. Default `all`
  (current behavior preserved). Root candidates = agents without `parentID`
  (consistent with deriveRows; late-join parents included).
- **Pure tree module** `src/web/tree.ts` (+ tests): `rootSessions(state)` and
  `subtreeOf(state, rootID)` — BFS over `parentID`, any depth (nested
  delegation safe), returns id set + depth map (root = 0).
- **Filtering**: GraphView, Gantt and header totals render the selected
  subtree only; Gantt axis rescales to the subtree time window. GraphView
  keeps its existing force layout, fed the filtered set + depth map.
- **Selector UI**: header pill row — "All" + one pill per root (status dot,
  agent name, agent count). Selected pill highlighted with the palette.
- **Deep link**: `?session=<id>` read on mount, updated via
  `history.replaceState` on change (no reload). Unknown/deleted selection
  falls back to `all`.
- **TUI synergy**: the `o` binding in TreePanel opens
  `<dashboard>/?session=<panel.sessionID>` — from any session you jump
  straight to ITS diagram (the panel knows its sessionID).
- Root deleted while selected → fall back to `all`.

## Constraints

- No new deps. Pure logic in `.ts` modules (vitest only includes
  `src/**/*.test.ts` — JSX stays build-covered only).
- Palette unchanged; selector styling via existing CSS variables.
